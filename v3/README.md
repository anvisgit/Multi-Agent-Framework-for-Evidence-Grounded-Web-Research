# Agentic Research Analyst

*A multi-agent, retrieval-augmented research pipeline that plans, gathers, interrogates, re-searches, and reports, entirely on local hardware. Large language models are fluent, confident, and, when left to their own devices, frequently wrong. This project examines whether a small ensemble of locally hosted models, each assigned a narrow professional role and constrained to cite only retrieved evidence, can produce a source-grounded research report from a single natural-language question. No cloud inference, no subscription, and no pretence of omniscience are required.

---

## 1. Research Question

> **Can a team of small, locally run language models, each restricted to one specialised role and bound to retrieved web evidence, produce a research report that is structured, traceable to its sources, and candid about its own limitations?**

1. Does decomposing research into discrete roles yield more reliable output than a single monolithic prompt?
2. To what extent does retrieval-augmented generation, combined with a "sources only" constraint, suppress hallucination in small models?
3. Can a self-critique stage, followed by a targeted second search, meaningfully close the gaps it identifies?

## 2. Aim

To design and implement an autonomous, privacy-preserving research assistant that converts a single query into a cited, structured report, demonstrating that credible machine-assisted research does not depend upon proprietary, paid infrastructure.

## 3. Objectives

1. **Decompose** a broad query into distinct, searchable angles.
2. **Retrieve** live evidence from the open web and index it semantically.
3. **Extract** verifiable facts with attribution, and record what the sources failed to cover.
4. **Critique** the findings, then **act on the critique** with a second, targeted search round.
5. **Compose** a formal report whose references are generated from pages actually retrieved, never from the model's imagination.
6. **Remember** earlier reports so that follow-up questions build upon them.
7. **Operate locally**, so that no query or finding leaves the user's machine.

## 4. Methodology

```
 Query
   |
   v
[ Validation ] ------- rejects vague or malformed questions
   |
   v
[ 1. Planner ] ------- 3 keyword searches, one per analytical angle
   |
   v
[ Retrieval ] -------- DuckDuckGo -> scrape paragraphs -> pages
   |
   v
[ RAG ] -------------- chunk (800 chars, 150 overlap) -> embed (nomic-embed-text)
   |                   -> ChromaDB (cosine) -> top-k chunks nearest the question
   v
[ 2. Researcher ] ---- facts with source and URL; "not found" list
   |
   v
[ 3. Critic ] -------- missing facts, weak claims, follow-up searches
   |
   v
[ Round 2 ] ---------- follow-up searches -> RAG -> additional facts (merged)
   |
   v
[ 4. Writer ] -------- Executive Summary, Key Findings, Limitations
   |                   (+ prior report from memory, if this is a follow-up)
   v
[ References ] ------- generated by code from retrieved URLs
   |
   v
 reports/*.txt, memory.json, on-screen report
```

### 4.1 Agent roles

| Stage | Role | Principal constraint |
|---|---|---|
| Planner | Research strategist | Non-overlapping keyword phrases |
| Researcher | Meticulous analyst | Facts only; numbers copied verbatim; gaps listed |
| Critic | Sceptical reviewer | Names specific gaps; proposes follow-up searches |
| Writer | Professional analyst | Supplied facts only; must disclose limitations |

### 4.2 Safeguards against hallucination

- **Open-book prompting.** Every agent is told to use only the material supplied.
- **Semantic retrieval.** Only the passages most relevant to the question reach the Researcher.
- **Explicit ignorance.** Unfound information is listed, and carried into a Limitations section.
- **Adversarial review followed by action.** The Critic's gaps trigger a second search.
- **Verified references.** The References list is assembled by code from retrieved URLs, so the model cannot fabricate one.
- **Output hygiene.** Leaked reasoning ("Thought:", "Final Answer:") and chatty openers are stripped.

## 6. Technology

| Component | Purpose |
|---|---|
| [Ollama](https://ollama.com) | Local model hosting |
| `qwen2.5:1.5b` | Reasoning model (substitutable in `research.py`) |
| `nomic-embed-text` | Local embeddings for RAG |
| ChromaDB | In-memory vector store |
| `ddgs`, `requests`, `beautifulsoup4` | Search and page extraction |
| Streamlit | Web interface |

## 7. Installation

```bash
# 1. Install Ollama (https://ollama.com), then pull the models
ollama pull qwen2.5:1.5b
ollama pull nomic-embed-text

# 2. Install dependencies
pip install -r requirements.txt
```

## 8. Usage

```bash
python research.py                  # terminal
python -m streamlit run app.py      # web interface
```

Enter a **specific** question. Vague queries are rejected by design.

| Rejected | Accepted |
|---|---|
| `analyze NVIDIA` | `NVIDIA Blackwell GPU data center deployment 2024` |
| `tell me about apple company` | `Apple Vision Pro enterprise adoption and competitors` |

A second question in the same session is treated as a follow-up and builds on the previous report.

## 9. Expected Output

1. Executive Summary
2. Key Findings
3. Limitations
4. References (retrieved pages)

The web interface additionally exposes the plan, the retrieved evidence, the extracted facts, the critique, and the round-2 findings.

## 10. Limitations

- **Retrieval bounds quality.** Paywalled or script-rendered pages yield little or nothing.
- **Small models err.** A 1.5B-parameter model follows formats imperfectly; the Critic's `SEARCH:` lines are occasionally omitted, in which case round 2 is skipped.
- **Verification is shallow.** The system confirms that a claim appears in a source, not that the source is correct.
- **No formal evaluation yet.** Claims about reduced hallucination remain unmeasured.
- **Latency.** Several sequential model calls take minutes on consumer hardware.
- **Memory is crude.** Only the most recent report is supplied to the Writer, truncated to 2,000 characters.

## 11. Future Work

- A **systematic evaluation** against single-prompt and no-RAG baselines, to answer Sub-questions 1 to 3 empirically.
- **Source-quality scoring**, weighting primary and institutional sources above aggregators.
- **Claim-level verification**, checking each sentence of the report against the retrieved chunks.
- **Persistent vector memory**, so earlier research is retrievable rather than merely appended.
- Support for **larger models** and a model-per-role configuration.
